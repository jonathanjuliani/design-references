## Taken

- A scheduled payment is created inside the normal pay flow: the person, the amount, then Scheduled, then a date and whether it repeats.
- The list has two modes. Calendar groups what is coming by date. Manage is the list of the scheduled items.
- Cancel sits on the item and is available until the payment is marked sent. After that, help says it cannot be cancelled from those settings.
- Theme is a choice in profile settings. On a recent iOS it can follow the phone. Help names a minimum app version. Neither theme was shown, so state colors were not checked.

## Rejected

- Using an outgoing scheduled payment as the model for a merchant's upcoming charge. Here the user is the sender.
- A theme that needs the app to be restarted before it applies. Help mentions that restart on iOS. A setting should apply when it is chosen.

## Not applicable here

- Pix, a receivables list, a guest page, and a playful empty state. No in-app copy of that kind was in the article.
- Detecting a subscription from past card charges. This flow starts when the user decides to send money later.
